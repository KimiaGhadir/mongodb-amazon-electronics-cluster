# کلاستر توزیع‌شده MongoDB برای تحلیل داده‌های Amazon Electronics

این پروژه با هدف طراحی و پیاده‌سازی یک سیستم پایگاه داده توزیع‌شده با استفاده از MongoDB انجام شده است. در این پروژه داده‌های متادیتای محصولات Amazon Electronics در یک کلاستر سه‌نودی MongoDB ذخیره شده و قابلیت‌هایی مانند پردازش داده، بهینه‌سازی Queryها، Index گذاری، مدیریت خطا و بررسی عملکرد سیستم پیاده‌سازی شده است.

## معرفی پروژه

در این پروژه از دیتاست Amazon Electronics Metadata استفاده شده است. هر رکورد این دیتاست اطلاعات یک محصول شامل شناسه محصول، عنوان، دسته‌بندی‌ها و ویژگی‌های فنی محصول را شامل می‌شود.

به دلیل حجم بالای داده‌ها، فرایند ورود اطلاعات به صورت Streaming انجام شده تا کل دیتاست به صورت همزمان وارد حافظه نشود.

## معماری سیستم

سیستم شامل یک MongoDB Replica Set با سه Node است:

```
Node 1 : 27017
Node 2 : 27018
Node 3 : 27019
```

در هر لحظه یکی از Nodeها به عنوان Primary فعالیت می‌کند و دو Node دیگر به عنوان Secondary وظیفه نگهداری Replica را دارند.

در این پروژه:

* عملیات Write فقط روی Primary انجام می‌شود.
* عملیات Read می‌تواند بین Nodeهای مختلف توزیع شود.
* در صورت از دست رفتن Primary، MongoDB به صورت خودکار یک Secondary را به عنوان Primary جدید انتخاب می‌کند.

## پردازش و طراحی داده

در مرحله پردازش داده دو تغییر اصلی روی ساختار اولیه انجام شده است.

### تبدیل دسته‌بندی‌ها به ساختار Flat

ساختار درختی Category محصولات به یک آرایه تبدیل شده است تا جستجو در تمام سطوح دسته‌بندی با سرعت بیشتری انجام شود.

مثال:

```json
{
  "categories": [
    "Electronics",
    "Computers",
    "Laptops"
  ]
}
```

### مدل‌سازی ویژگی‌های فنی

به دلیل متفاوت بودن ویژگی‌های محصولات مختلف، فیلد details به صورت آرایه‌ای از Key-Value ذخیره شده است.

مثال:

```json
{
  "details": [
    {
      "k": "RAM",
      "v": "16GB"
    }
  ]
}
```

این روش امکان Index گذاری و Query روی ویژگی‌های مختلف محصولات را فراهم می‌کند.

## Query های پیاده‌سازی شده

پروژه شامل Queryهای اصلی زیر است:

### 1. جستجو بر اساس شناسه محصول

دریافت اطلاعات کامل یک محصول با استفاده از شناسه Amazon.

### 2. نمایش Catalog با Pagination

دریافت محصولات به صورت صفحه‌بندی شده برای جلوگیری از بارگذاری حجم زیادی از داده.

### 3. جستجوی Category

پیدا کردن محصولات مربوط به یک دسته خاص بدون توجه به سطح قرارگیری آن در ساختار دسته‌بندی.

### 4. جستجوی ویژگی فنی

پیدا کردن محصولاتی که دارای یک ویژگی مشخص با مقدار مشخص هستند.

### 5. جستجوی ترکیبی

امکان ترکیب چند ویژگی با منطق‌های:

* AND
* OR

## Index گذاری و بهینه‌سازی

برای افزایش سرعت Queryها، Indexهای مناسب روی فیلدهای پرکاربرد ایجاد شده‌اند.

از جمله:

* Index روی شناسه محصول
* Multikey Index روی Category
* Compound Index روی ویژگی‌های فنی
* Text Index برای جستجوی متنی

عملکرد Queryها قبل و بعد از Index گذاری با استفاده از MongoDB Explain بررسی شده است.

## مدیریت خطا و Failover

برای بررسی قابلیت اطمینان سیستم، سناریوی Failover پیاده‌سازی شده است.

در این سناریو:

1. Primary متوقف می‌شود.
2. Replica Set یک Node جدید را به عنوان Primary انتخاب می‌کند.
3. Node قبلی پس از بازگشت، دوباره به عنوان Secondary وارد کلاستر می‌شود.

## بررسی Race Condition

برای بررسی مشکل همزمانی، یک سناریوی آپدیت همزمان روی یک فیلد مانند تعداد بازدید محصول طراحی شده است.

برای جلوگیری از از دست رفتن تغییرات از عملیات Atomic Update در MongoDB استفاده شده است.

## ارزیابی عملکرد

عملکرد سیستم در سه حالت بررسی شده است:

1. Standalone بدون Index
2. Cluster بدون Index
3. Cluster بهینه شده با Index

معیارهایی مانند زمان پاسخ Query و Throughput سیستم اندازه‌گیری و تحلیل شده‌اند.

## اجرای پروژه

ابتدا کلاستر MongoDB را اجرا کنید:

```bash
docker compose up -d
```

سپس ابزارهای Python را اجرا کنید:

```bash
python src/ingest.py
```

برای ساخت Indexها:

```bash
python src/indexes.py create
```

برای اجرای Queryها و Benchmarkها می‌توانید از فایل‌های موجود در پوشه `src` استفاده کنید.
